# DARK SOUL — A World of Feelings, Stories & Prompts

موقع عربي RTL كامل: واجهة ثابتة (HTML/CSS/JS) + خادم واحد `api/app.js` على Vercel + قاعدة بيانات Supabase.
بدون الخادم يعمل الموقع كاملًا في «الوضع المحلي»، ومع الخادم تُفتح الحسابات والإدارة والمجتمع.

## الملفات
- `index.html` `style.css` `content.js` `prompts.js` `app.js` `tools.js` `net.js`: الموقع.
- `admin.html` `admin.js`: لوحة الإدارة (صفحة منفصلة، الصلاحيات تُفحص على الخادم).
- `api/app.js`: الخادم كله في ملف واحد. `supabase.sql`: مخطط القاعدة. `vercel.json` `robots.txt` `sw.js` `manifest.webmanifest`.

## ما يعمل
**بدون خادم:** 23 صفحة، 71 نصًا و30 برومبتًا و6 قصص و20 اقتباسًا، بحث، مفضلة محلية، مصنع البوستات، استوديو PNG، نيون، PWA.
**مع Supabase:** تسجيل حساب/دخول/استعادة كلمة المرور/حذف الحساب، مزامنة المفضلة والإعدادات، إدارة المحتوى (إضافة/تعديل/حذف/تمييز/إخفاء/جدولة)، تصنيفات جديدة، إحصائيات مجهولة الهوية وترتيب «الأكثر رواجًا» الحقيقي، مجتمع (منشورات بمراجعة، تعليقات، بلاغات، إخفاء تلقائي عند 3 بلاغات، حظر)، مساحة ترويجية، التحكم برسالة الترحيب والشعار واللون، روابط مشاركة `/p/<id>` مع وسوم Open Graph وخريطة موقع.
**الذكاء الاصطناعي:** اختياري عبر `AI_API_KEY`، ولا يظهر إلا إذا كان مضبوطًا فعلًا.

## التنفيذ من الهاتف (بالترتيب)
**1) Supabase** — supabase.com ← New project (احفظ كلمة سر القاعدة).
 - SQL Editor ← New query ← الصق محتوى `supabase.sql` كاملًا ← Run.
 - Project Settings ← API: انسخ `Project URL` و`anon public` و`service_role`.
 - Authentication ← Providers ← Email: لتجربة أسهل أوقف «Confirm email»، أو اتركه وسيصل المستخدمين بريد تفعيل.

**2) GitHub** (فعّل «موقع سطح المكتب» في المتصفح): مستودع جديد ← Add file ← Upload files ← ارفع كل ملفات الجذر (كل شيء ما عدا مجلد `api`) ← Commit.
 ثم Add file ← **Create new file** ← اكتب الاسم `api/app.js` (الشرطة المائلة تنشئ المجلد) ← الصق محتوى ملف `api/app.js` ← Commit.

**3) Vercel** — Add New Project ← اختر المستودع ← Framework: Other ← قبل Deploy افتح Environment Variables وأضف:
`SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_KEY` (و`SITE_URL` برابط موقعك، و`AI_API_KEY` اختياريًا) ← Deploy.
مفتاح `service_role` سري: لا تضعه في أي ملف ولا ترسله لأحد.

**4) Supabase** ← Authentication ← URL Configuration: ضع رابط موقعك في Site URL وأضفه في Redirect URLs (لازم لاستعادة كلمة المرور).

**5) المدير الأول:** سجّل حسابًا من الموقع (#/account). ثم في Supabase SQL Editor شغّل (بعد تغيير البريد):
`update public.profiles set role = 'admin' where id = (select id from auth.users where email = 'بريدك');`

**6) لوحة الإدارة:** افتح `رابط-موقعك/admin.html` ← سجّل الدخول ← تبويب «استيراد» ← «ابدأ الاستيراد» (ينقل المحتوى الحالي للقاعدة مرة واحدة) ← تبويب «الإعدادات» لتفعيل المجتمع وضبط الترحيب والشعار.

## الأمان
- كل الجداول مقفلة (RLS بلا سياسات)، والمتصفح لا يصل للقاعدة؛ كل شيء عبر `api/app.js` الذي يتحقق من الجلسة والدور في كل طلب.
- لا كلمات مرور ولا مفاتيح داخل الكود. الإدارة تُمنح من القاعدة فقط.
- حدود طلبات (تسجيل، دخول، استعادة، مجتمع في القاعدة نفسها: 3 منشورات/ساعة و10 تعليقات/ساعة)، منع الروابط المتعددة والتكرار، وتنظيف المدخلات.
- الإحصائيات لا تخزّن IP ولا أي هوية.

## حدود صريحة
- الحد المؤقت لطلبات الـ IP (الدخول والتسجيل) في ذاكرة الدالة وقد يتجزأ بين النسخ؛ للإنتاج الكبير استخدم Upstash/Vercel KV.
- الروابط `#/` الأصلية لا تفهرسها محركات البحث؛ روابط `/p/<id>` بعد الاستيراد هي التي تُفهرس.
- الإشراف يدوي (مشرف بشري يراجع)؛ لا يوجد فلتر آلي للمحتوى سوى منع الروابط والتكرار.
- Supabase وVercel خدمات خارجية لها حدود وأسعار خطتها المجانية وقد تتغير؛ راجعها قبل الاعتماد عليها.
- لم تُجرَّب الواجهة على متصفح حقيقي من طرفي؛ اختبرت المنطق والخادم بمحاكاة (الصلاحيات، التحقق، الحقن، الاستجابات).
